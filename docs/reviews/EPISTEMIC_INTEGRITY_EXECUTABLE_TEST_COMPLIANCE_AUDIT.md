# Epistemic Integrity — Executable Test Compliance Audit

Ratification audited: Constitutional Amendment No. 1 — Epistemic Integrity, Version 1.0, commit `2d5de9a9e4b577d443d90a6c75fc5f0bb9ca3fb2` ("Ratify Epistemic Integrity Amendment v1.0"). 19 Articles, 69 Constitutional Tests.

---

## 1. Executive Summary

The ratification commit changed documentation only. This audit finds that the existing executable test suite provides **no fully enforced coverage of any of the 69 Constitutional Tests**. Coverage breaks down as: 0 FULLY ENFORCED, 8 PARTIALLY ENFORCED, 3 COMPATIBLE BUT UNTESTED, 52 NOT IMPLEMENTED, 4 CONFLICTING TEST OR BEHAVIOUR, 2 NOT YET APPLICABLE.

The codebase predates the Amendment and was never written against its vocabulary. Its strongest genuine alignment is in Memory Core (`src/interfaces/MemoryCore.kt`), whose `Assertion`/`Provenance`/`ContentNature` model independently embodies several Article III/VI/VIII/IX principles and is well-tested on its own terms. But Memory Core is architecturally disconnected from the live reasoning-and-response pipeline: `DefaultReasoningContextAssembler` reads from the older `MemoryStore`/`MemoryRecord` subsystem (via `MemorySource`), not from Memory Core's `Assertion`/`Provenance` model, so none of Memory Core's epistemic scaffolding currently reaches anything a user actually sees. This is the audit's single highest-value finding and is developed in Section 15.

Four genuine conflicts were found, all in the World Model: a required (non-nullable) `confidence: Double` field that forces fabricated precision where honest uncertainty should be expressible (Article XIII); a single-scalar confidence comparison that is the sole determinant of whether new information supersedes old (Article XI §1's "no single factor" rule); an update policy that rejects and discards a weaker competing observation rather than preserving it as an unresolved competing proposition (Article IV/VII); and belief replacement that discards the prior belief and the observation's own `sourceTimestamp` with no history retained (Article XVI). These are documented, intentional, tested design decisions — not omissions — and are the most serious findings in this audit because they are load-bearing, working code that actively does the opposite of what four separate Articles require.

Outside Memory Core and World Model, the Reasoning Provider surface (`ReasoningProviderResponse`: `Goal`/`Reply`/`NoAction`) and the response-composition/delivery pipeline (`ResponseComposer`, `ResponseDelivery`) carry no evidential-state, confidence, provenance, or uncertainty field of any kind — proven by direct reading of the types and by tests that confirm text is passed through as opaque strings. The agent/planning/execution stack has one genuinely strong, well-tested constitutional analogue: a structural, multi-layered separation between proposal, authorization, and execution (Article XV's "cognition proposes, epistemic governance determines what may be claimed" is a direct restatement of a pattern this codebase already enforces rigorously for authority — just not yet for evidential status). No document-transformation capability (OCR, extraction, translation) exists to test against Article IX at all.

## 2. Audit Method

Four parallel, read-only fact-finding passes were conducted against the actual source at `/sessions/dreamy-sharp-ramanujan/mnt/Parker/parker-platform/parker-platform` (Memory Core / Knowledge Memory; Reasoning Context / World Model; Conversation / response composition; Agent / Planning / Tool / Event / Audit). Each pass read production Kotlin files and their corresponding test files directly, reporting file:line citations and, for every test function, a factual sentence describing what the test body actually asserts — not what its name implies. No conclusion was drawn from a class name, KDoc comment, architecture document, or successful compilation; every classification below is grounded in an assertion actually present in a test, or explicitly marked absent where no such assertion exists. No production code, test, or constitutional document was modified in the course of this audit. Nothing was staged, committed, or pushed.

## 3. Constitutional Applicability

The Amendment binds "every reasoning provider, memory system, retrieval engine, document processor, world model, workflow, agent, tool, plugin, and future capability" (Article XIX). Every subsystem named in the audit scope exists in the codebase in some form except document processing (no OCR/extraction/translation capability exists at all) and a working `AuditService` (the interface exists; no implementation, and its own referenced types `AuditRecord`/`AuditQuery`/`AuditRecordId` are undefined anywhere in the repository). Two Constitutional Tests (CT-EI-33, tied to document transformation, and CT-EI-69, a textual interpretive-hierarchy rule with no executable analogue) are classified NOT YET APPLICABLE for that reason; every other test is applicable now, because every other Article governs capability that already exists in some form (memory, reasoning context, world belief, conversation, agent/plan/tool execution).

## 4. Current Executable Test Baseline

100 test files were catalogued under `tests/`. This audit directly read and reports on 63 of them plus 12 test-double/fixture files (which contain no assertions), spanning: 15 Memory Core / Knowledge Memory files, 15 Reasoning Context / World Model files, 11 Conversation / response files, 18 Agent / Planning / Tool / Event files. The remaining test files (largely `Identifiers`, `Principal`, `Permission`, `Resource`, `Module`, `ToolResolution` contract tests, and channel/tool-binding tests) are outside the audit scope because they test authority/identity/resource mechanics the base Parker Constitution already governs, not epistemic representation. The existing suite passed before and after the ratification commit; that fact establishes nothing about Epistemic Integrity compliance, since the ratification commit touched no code the suite exercises, and no test in the suite currently asserts against the Amendment's vocabulary (evidential state, propositional integrity, burden of justification, evidential integrity) at all.

## 6. Memory Core Compliance

Memory Core is the strongest-aligned subsystem in the codebase, and its alignment appears deliberate rather than coincidental: its own KDoc uses language ("never automatically truth," "must never be silently defaulted") that reads as if written with exactly this kind of constitutional discipline in mind, even though it predates the Amendment.

- **Storage does not create truth**: `Assertion` carries a lifecycle `status` (`ACTIVE/DISPUTED/SUPERSEDED/ARCHIVED/DELETED`), never a "verified" or "true" status, and its own KDoc states directly that "An Assertion is never automatically truth, and its own existence never causes any other record's status to change" (`MemoryCore.kt:410-420`). `AssertionTest.kt` tests this at the field-shape level (exactly six fields, no truth/support/contradiction field, `AssertionTest.kt:105-116`) and at the side-effect level (constructing an Assertion leaves an unrelated Entity unchanged, `AssertionTest.kt:121-144`). **Well tested, genuinely compliant with the relevant part of Article III.**
- **Provenance distinct from evidential weight**: `Provenance` and `Assertion.confidence` are separate concerns; nothing in Memory Core conflates them. Untested directly, but nothing conflicts either — **COMPATIBLE BUT UNTESTED** as a standalone claim.
- **`ContentNature` distinguishes original/derivative/summarised/inferred/unknown**: Directly implemented and tested (`MemoryCoreContractsTest.kt`, `ProvenanceTest.kt`). **This is real, tested coverage of the core idea behind Article IX** — but Article IX's own vocabulary (original/derivative/extract/transcript/translation/summary/reconstruction) is more granular than `ContentNature`'s five values, and no test maps one to the other explicitly.
- **Transformation chains traceable**: Fields exist (`derivedFrom`, `processingHistory`) but are untested with populated content — **COMPATIBLE BUT UNTESTED**.
- **Unknown values explicit**: Strongly tested (`ProvenanceTest.kt` — every optional field accepts null; `ContentNature.UNKNOWN` is "a fully valid, non-erroring construction"). **Genuinely compliant.**
- **Confidence not treated as truth probability**: No test asserts this relationship either way, because nothing in Memory Core treats confidence as anything other than a bounded float; there is no truth-probability interpretation to conflict with. **COMPATIBLE BUT UNTESTED.**
- **Dispute and supersession preserve historical state**: Tested directly — a `DELETED` record remains fully retrievable with its status changed, not its content removed (`InMemoryMemoryCoreTest.kt:405-413`); the full 5×5 lifecycle transition table is exhaustively tested. **Genuinely compliant with Article XVI's non-erasure principle, for status changes.** No test proves field-level content amendments preserve prior values, because no content-amendment operation exists — only status transitions.
- **Deletion does not silently rewrite history**: Same evidence as above — DELETED is a status flag, not content removal. **Genuinely compliant.**
- **Retrieval does not strip provenance**: Every record kind carries `provenanceId` by reference; `findByProvenance` is tested. No test explicitly re-fetches a full `Provenance` object post-round-trip and diffs every field. **PARTIALLY ENFORCED.**
- **`SUPPORTS`/`CONTRADICTS` don't themselves prove or disprove an assertion**: The relationship-type string constants are tested to exist; **no test anywhere confirms that creating a `SUPPORTS` or `CONTRADICTS` relationship leaves the referenced record's own status unchanged.** This is a genuine, material gap — nothing currently prevents a future change from silently attaching truth-resolution behavior to relationship creation. **COMPATIBLE BUT UNTESTED**, and flagged in Section 17 as a new test required now.

## 7. Knowledge Memory Compliance

"Knowledge Memory" in the audit instructions maps to the same Memory Core interface as Section 6; there is no separate "Knowledge Memory" type in the codebase distinct from Memory Core. The findings in Section 6 apply. The one architecturally distinct sibling — the older `MemoryStore`/`MemoryRecord`/`MemorySource` subsystem — has none of Memory Core's epistemic scaffolding (no `ContentNature`, no `Provenance`, no `Assertion` distinction) and is the subsystem actually wired into live reasoning (Section 15). Its own tests (`InMemoryMemoryStoreTest.kt`) confirm `forget()` performs genuine content deletion (the record is removed from the retrievable map), retaining only a bare identifier in a separate audit set — architecturally the opposite of Memory Core's preserve-with-status-change approach, and a real, tested inconsistency between Parker's two memory subsystems' approaches to deletion.

## 8. Retrieval Compliance

`MemoryRetrieval` (Memory Core) supports lookup by entity, document, assertion, relationship, time range, metadata, and provenance, each independently tested for construction and basic filtering (`MemoryCoreInterfacesTest.kt`, `InMemoryMemoryCoreTest.kt`). No test proves retrieved records carry their full evidential context (provenance object, not just its id) forward into whatever consumes the retrieval result — because nothing currently consumes Memory Core's retrieval surface downstream in the reasoning pipeline at all (Section 15). `MemorySource.recall` (the interface actually wired into reasoning) is explicitly documented as "never a second source of truth... must never construct a MemoryRecord itself, never mutate a record" (`MemorySource.kt:46-51`) and this passivity is tested (`recall returns exactly what retrieve would`, `InMemoryMemoryStoreTest.kt:276`) — a genuine, tested guarantee that retrieval doesn't fabricate content, though it says nothing about provenance preservation since the `MemoryStore` model this interface serves carries none.

## 9. Reasoning and Representation Compliance

This is the most consequential subsystem for the Amendment and the weakest in coverage. `ReasoningContext` is an unstructured list of prose strings (`ReasoningProvider.kt:34-40`); `ReasoningProviderResponse` is exactly `Goal(text)` / `Reply(text)` / `NoAction` — three shapes, none carrying an evidential-state, confidence, or uncertainty field. `ReasoningPromptBuilder` and `ReasoningResponseParser` are both proven, by direct test, to do purely mechanical work: verbatim string concatenation with a fixed instruction suffix, and exact-prefix string matching, respectively — neither examines propositional content, assumptions, or framing. `DefaultReasoningContextAssembler` is proven not to rank, score, reconcile, or interpret anything it assembles (explicit KDoc, matched by test behavior), and proven to render confidence values honestly when present (never fabricated when absent) — the one genuinely positive, tested finding in this subsystem, captured as CT-EI-54 PARTIALLY ENFORCED. `GoalPlanningHandoffCoordinator` extracts `Goal.text` and hands it directly to the planner with no intervening "this is a proposal, not settled fact" gate visible in the file, though the planner's own structural separation from execution authority (Section 12) provides an authority-level, if not evidential-level, safeguard.

## 10. World Model Compliance

Covered in depth in the matrix (CT-EI-05, 41, 45-48, 56, 58-59). Summary: `WorldModel` structurally supports exactly one current belief per subject, with acceptance gated by a single required, non-nullable confidence float compared against the existing belief's confidence — the update policy accepts on higher-or-equal confidence and rejects (discarding) on lower. The authoritative timestamp is always acceptance time, never the observation's own claimed time, and this is tested as the intended design ("never trusting a source-reported one"), not a bug. All four CONFLICTING TEST OR BEHAVIOUR findings in this audit trace to this subsystem. `InMemoryWorldModel` is well-engineered and thoroughly tested (concurrency safety, staleness handling, policy injection) on its own terms — the conflicts are with the Amendment's requirements, not with World Model's own internal design goals, which were set before the Amendment existed.

## 11. Conversation and User-Authorship Compliance

`InboundOwnerMessage.text` (the user's own words) is passed by object/value equality, unmodified, from `CommunicationIntake` through `ConversationEngine.submitTurn` to `Turn.message` to `ConversationHistorySource.history()` — verified by multiple tests asserting equality against the original (`InMemoryConversationEngineTest.kt`, `InMemoryCommunicationIntakeTest.kt`). No summarization or paraphrase code exists anywhere in this cluster, so there is nothing to test a "distinguish summary from full source" obligation against — this functions as a genuine, if incidental, alignment with the companion `user-authorship-and-evidence.md` document's principle that Parker does not rewrite a user's own account, though it predates and was not tested against either that document or this Amendment. No uncertainty-disclosure, assumption-disclosure, or dissent-preservation mechanism exists anywhere in this cluster.

## 12. Agent, Workflow and Tool Compliance

The strongest positive structural finding in the entire audit, though not directly an Epistemic Integrity obligation: proposal (`agent.*`/`planner.*` events), authorization (`permission.*` events, Permission Engine evaluation), and execution (`execution.*` events) are proven, extensively and directly, to be temporally and causally distinct, individually timestamped, and structurally gated — a `Rejected` authorization is proven to make execution structurally unreachable (`InMemoryTaskManagerRuntimeTest.kt:765-798`, zero-call-count assertions), and `GoalPlanningHandoffCoordinator` is proven to hold no reference to any authorization or execution mechanism at all (`GoalPlanningHandoffCoordinatorTest.kt:313-332`). This is exactly the "cognition proposes, epistemic governance determines what may be claimed" separation Article XV calls for — just applied today to authority, not yet to evidential status, since `TaskProposal.riskEstimate`/`rationale` are proven not to influence any decision (`DefaultPlanDecisionTest.kt:118-126`) and no evidential-sufficiency gate exists on a Goal or plan's underlying belief. `AuditService` has no implementation and undefined referenced types; the only working event-observation mechanism (`EventCollector`) is explicitly documented as test-only, not a production audit capability (`EventCollector.kt:21-23`).

## 13. Conflicting Tests or Behaviours

Consolidated from the matrix (CT-EI-05, 48, 56, 58), all in World Model:

1. **Single-belief-per-subject with confidence-based rejection** (CT-EI-05, 24) — a weaker competing observation is rejected and discarded rather than preserved as an unresolved competing proposition.
2. **Required, non-nullable confidence forcing false precision** (CT-EI-56) — `WorldBelief`/`WorldObservation.confidence: Double` cannot express "uncertainty that cannot be meaningfully quantified"; Memory Core's equivalent field is nullable by contrast.
3. **Single-scalar confidence as sole update gate** (CT-EI-48) — no other Article XI factor (provenance, contemporaneity, independence, corroboration) participates in the accept/reject decision.
4. **Belief overwrite discards prior belief and source-reported time with no history** (CT-EI-58, 59) — `observe()` on `Accepted` overwrites the map entry; no test or mechanism retains what was believed before, or when the observation claimed the event occurred.

## 14. Compatible but Untested Obligations

CT-EI-32, 38, 63 (Section 5 matrix) — Memory Core fields exist that could satisfy these obligations (`processingHistory`, `derivedFrom`, `integrityInformation`, the `AMENDS`/`SUPERSEDES` relationship types) but no test proves them populated and working end-to-end. These are the lowest-risk gaps in this audit: nothing conflicts, the scaffolding is present, and closing them is a matter of writing tests against existing structure, not building new capability.

## 15. False-Positive Compliance Risks

Ordered by materiality:

1. **Memory Core's epistemic scaffolding does not protect anything a user sees.** This is the highest-value finding of this audit. `DefaultReasoningContextAssembler` — the component that actually builds what a Reasoning Provider sees — depends on `MemorySource`, which is implemented by `InMemoryMemoryStore` over the older `MemoryStore`/`MemoryRecord`/`CandidateMemory` types. These types have no `Provenance`, no `ContentNature`, no `Assertion`/truth distinction of any kind. Memory Core (`Assertion`/`Provenance`/`ContentNature`, `MemoryCore`/`MemoryRetrieval`) is a separate, parallel, better-designed subsystem that is not consumed anywhere in the live conversational pipeline reviewed by this audit. A reviewer skimming Memory Core's test suite (Section 6) could reasonably, and wrongly, conclude Parker's memory-backed representations are constitutionally sound. They are not currently reachable by anything Parker says to a user.
2. **Confidence rendering (CT-EI-54) proves honesty at one stage only.** `DefaultReasoningContextAssemblerTest.kt` proves confidence is not fabricated when building the *prompt*. Nothing proves the underlying language model's free-text `Reply`/`Goal` output actually preserves or reflects that confidence — the model could discard, invert, or overstate it in its response text, and no test in the suite could currently detect that, because `ReasoningProviderResponse` has no structured field to check.
3. **"Provenance exists" is not "provenance is enforced downstream."** Tests proving `Provenance` is a mandatory, validated field at Memory Core creation time (CT-EI-27/28) prove nothing about whether a consumer of retrieved data is obligated, or even able, to surface that provenance later. No consumer currently exists to test.
4. **Structural authority-separation tests (Section 12) are not evidential-sufficiency tests.** A reviewer could mistake the extensive, genuinely rigorous propose/authorize/execute separation testing for evidence that plans and goals are evidentially vetted before acting on them. They are not — the separation gates who is *permitted* to act, not whether the underlying belief driving the action is *justified* (`DefaultPlanDecisionTest.kt` explicitly proves `riskEstimate` does not influence selection).
5. **`ContentNature` existing does not mean it is checked.** No code path reads a record's `ContentNature` and branches on it (e.g., to require disclosure before treating a `SUMMARISED` record as equivalent to `ORIGINAL`). The field is populated and retrievable, never consulted.
6. **A relationship-type constant existing does not mean its semantics are enforced.** `SUPPORTS`/`CONTRADICTS`/`DISPUTES` are strings a caller may attach to a `Relationship`; nothing in `InMemoryMemoryCore` reads `relationshipType` and changes any other record's state as a result — which is actually the *correct* behavior per Article VII/XI (a relationship shouldn't itself resolve truth), but it also means the string carries no more enforced meaning than any other value a caller could supply, per `RelationshipTest.kt`'s own proof that `relationshipType` accepts arbitrary, non-recognised strings.

## 16. Existing Tests Requiring Correction (Register A)

1. `tests/runtime/InMemoryWorldModelTest.kt` — "a weaker contradictory observation is rejected and does not alter current belief"; `tests/runtime/DefaultWorldModelUpdatePolicyTest.kt` — "a weaker contradictory observation is rejected, not silently discarded" (misleadingly named — it is in fact discarded from the belief store, only a `Rejected` result value is returned). Conflicts with CT-EI-05/24.
2. `tests/contracts/WorldModelContractsTest.kt` — "a WorldBelief confidence outside 0.0 to 1.0 is rejected" and the paired boundary-acceptance tests; `tests/runtime/InMemoryWorldModelTest.kt` and `DefaultWorldModelUpdatePolicyTest.kt` confidence-comparison tests generally. Conflicts with CT-EI-56 (non-nullable confidence) and CT-EI-48 (single-factor gating).
3. `tests/runtime/InMemoryWorldModelTest.kt` — "the World Model assigns the authoritative timestamp, never trusting a source-reported one." Conflicts with CT-EI-40/58/59 (both timestamps should be distinguishable and preserved, not one discarded).

## 19. Production-Code Implications

The single highest-leverage production change is wiring Memory Core into the live reasoning pipeline (replacing, or supplementing, `MemorySource`'s current basis in `MemoryStore`) — without this, no amount of Memory Core hardening improves what a user actually receives. The second highest-leverage change is adding a structured evidential-state/confidence field to `ReasoningProviderResponse`, since almost every NOT IMPLEMENTED classification in Sections 5/9 traces back to this type carrying nothing but free text. Third: resolving the four World Model conflicts (Section 13) requires either a genuine redesign of `WorldBelief`/`DefaultWorldModelUpdatePolicy` (nullable confidence, multi-belief-per-subject or an explicit unresolved state, multi-factor weighing, retained history) or an explicit, documented decision that World Model is out of scope for Article XVI/XI and that "understanding" for constitutional purposes is carried by Memory Core instead. `AuditService`, `AuditRecord`, `AuditQuery`, and `AuditRecordId` need either a real implementation or explicit removal/deferral from the interface surface, since an interface with undefined referenced types and no implementer is presently dead weight that could mislead a future reviewer into believing an audit trail exists.

## 20. Recommendation

Do not treat the existing green test suite as evidence of Epistemic Integrity compliance in any communication about this ratification — it isn't, and four instances of it actively encode the opposite of what the Amendment requires. Prioritize, in order: (1) close the Memory Core / reasoning-pipeline disconnection (Section 15, Finding 1), since it is the precondition for every other improvement mattering to a user; (2) resolve the four World Model conflicts (Section 13), since they are live, tested, intentional contradictions, not gaps; (3) introduce the evidential-state taxonomy (Article IV) as a first-class type, since roughly three-quarters of the NOT IMPLEMENTED findings trace back to its absence; (4) work through Registers B and C in the order given. None of this requires touching the ratified constitutional text itself — the Amendment is sound; the codebase has not yet been built to it.
