## 3. Planning question

The question is not whether Qwen should replace Llama, whether any model is better, or whether a third live Knowledge Discoverability attempt should occur.

The planning question is:

> Does the accepted downstream operational trigger, read together with the existing but confounded DQ4 evidence, justify revising Family F's current experiment-scope exclusion far enough to permit a separately governed, non-qualifying alternative-model diagnostic - and, if so, what governance must precede any model call?

## 4. Evidence admitted for this planning decision

### 4.1 Unit 2-D DQ4

Unit 2-D tested `qwen2.5-coder:7b` and `llama3.2:3b` once each on the same `R01-direct` minimal-context fixture. Both missed the expected `REMEMBER` selection.

That evidence supports only a weak finding that protocol or prompt design may be a partial contributor. It supports no model ranking. The comparison is doubly confounded because model size and specialization differ simultaneously, and each model has only one exposure in that DQ4 cell.

### 4.2 Knowledge Discoverability Attempts 1 and 2

The accepted live-verification record establishes a real downstream dependency:

- Knowledge Discoverability implementation Units 1-5 are accepted;
- live closure remains blocked because no successful live promotion followed by recall was observed;
- Attempt 1's raw tag selection is unobserved and may not be assigned retrospectively;
- Attempt 2 directly captured `REPLY` on both turns from `llama3.2:3b`;
- no promotion occurred and live recall was therefore not exercised; and
- the exercised prompt/transmission/parsing/dispatch path behaved consistently with the captured response.

These attempts are admissible only as operational-impact and reopening-trigger evidence. They are not Family F experiment trials, are not qualification evidence, and must never be pooled with Unit 2-D or any future Family F campaign.

### 4.3 Existing Unit 3 remedy evidence

Families A, B, and C were tested at exploratory tier. Unit 3-E selected no remedy. Family C was not eliminated and did not fail a nonexistent zero-false-positive experimental gate; it was not selected after the total evidence was considered. No tested family supplies authority to skip Family F governance.

### 4.4 Absence of qualification evidence

No model, including `llama3.2:3b` or `qwen2.5-coder:7b`, has completed the Unit 3-A qualification-tier process for this role. Existing exploratory observations cannot be represented as qualification.

## 5. Reconsideration determination

**FAMILY_F_RECONSIDERATION=JUSTIFIED.**

The evidence-to-cost judgment has materially changed at the planning level because:

1. a separate, accepted downstream programme is blocked on live semantic selection;
2. the blocker reproduced twice operationally with the current live model, with Attempt 2 directly observing the wrong valid action tag;
3. DQ4 is too weak and confounded to answer whether a different model could materially alter the result;
4. Unit 3-E selected no remedy among the already-tested families; and
5. the Reopening Decision expressly activated Family F planning.

This is a prioritization and governance finding, not new comparative model evidence. It does not mean Family F is likely to succeed, cheaper overall, preferred, selected, or qualified.

## 6. Current contradiction that prevents direct execution

The existing Unit 3-B Scope Lock contains two simultaneously binding provisions:

- Section 3 classifies Family F as **EXCLUDED ON CURRENT EVIDENCE, EXPRESSLY REVISABLE BY FUTURE GOVERNANCE**; and

The contradiction is resolvable only by an express governance act. It must not be resolved implicitly by running a model first and documenting it afterward.

## 8. Required decision for the Unit 3-BF Scope Lock

The Unit 3-BF Scope Lock must make one explicit choice:

### Path 1 - retain the current qualification-first rule

Under this path, no bounded diagnostic is permitted. Any alternative-model evaluation must begin with the full Unit 3-A qualification process. The Scope Lock must then state that the cost remains proportionate and define the later qualification-governance chain without authorizing execution itself.

### Path 2 - create a narrow pre-qualification diagnostic exception

Under this path, the Scope Lock must expressly amend Unit 3-B Section 5, item 14 for Family F only. It must define a bounded diagnostic tier whose sole purpose is deciding whether full qualification investment is warranted.

The exception must not:

- qualify a model;
- select a remedy or deployment model;
- authorize production use;
- satisfy Unit 3-A's qualification thresholds;
- reuse its results as qualification exposures;
- authorize Knowledge Discoverability Attempt 3; or
- weaken the later full-qualification requirement if Family F advances.

This Planning Review recommends **Path 2 for Scope Lock consideration**, because the question being asked is whether full qualification expenditure is justified. That recommendation is not an amendment by itself; the current qualification-first rule remains binding until a Unit 3-BF Scope Lock expressly changes it and passes independent review.

## 9. Proposed diagnostic purpose

## 10. Minimum evidence surface for a future Scope Lock

The future Unit 3-BF Scope Lock must not authorize an `R01-direct`-only contest. A model that improves one positive Remember fixture while regressing other actions or producing false-positive consequential tags is not an acceptable diagnostic success.

At minimum, the Scope Lock must freeze:

1. the complete existing blind 23-fixture corpus as the primary semantic surface;
2. the existing expected action and content constraints without relabeling;
3. all relevant action families: `REMEMBER`, `REPLY`, `GOAL`, and `NOACTION`;
4. negative and adversarial Remember fixtures, including quoted, hypothetical, negated, embedded-tag, mixed-intent, and injection cases already governed by the corpus;
5. content-fidelity scoring separate from action-selection scoring;
6. representation validity separate from semantic correctness;
7. per-fixture and per-action reporting, never aggregate score alone;
8. identical prompt, parser, provider path, context profile, repository commit, and inference settings across comparison arms except for the model identity being isolated;
9. a pre-registered repeat count and ordering protocol;
10. cold/warm-state handling, latency, token counts, and resource observations; and
11. raw request/response capture sufficient to distinguish model output from parser or dispatch behavior.

The exact repeat count and context-profile subset remain decisions for the Unit 3-BF Scope Lock. They may not be improvised at execution time.

## 13. Resource and operational boundary

The two accepted Knowledge Discoverability attempts showed that available RAM can fall from approximately 4.1 GiB to approximately 1.5 GiB after loading `llama3.2:3b`. Historical records also identify `qwen2.5-coder:7b` as a materially larger model artifact. Those observations are planning evidence only; they do not establish a safe execution threshold for Qwen.

Accordingly:

1. the prior generic 2.0 GiB free-RAM gate is not automatically sufficient for an alternative-model run;
2. the Unit 3-BF Scope Lock must require a model-specific resource budget derived before execution;
3. the later Implementation Plan must define fail-closed RAM, disk, model-residency, timeout, and process-isolation checks;
4. only one governed diagnostic model may be resident when required by the resource plan;
5. no process belonging to the existing production Parker instance may be stopped, reconfigured, inspected beyond authorized read-only health checks, or used as the diagnostic runtime;
6. shared Ollama use, model loading/unloading, and interference risk require explicit authorization in the later plan;
7. a resource-gate failure must stop the run, not trigger an improvised smaller model, different quantization, changed context, or reduced corpus; and
8. no model download, pull, conversion, quantization, or deletion is authorized by this review.
