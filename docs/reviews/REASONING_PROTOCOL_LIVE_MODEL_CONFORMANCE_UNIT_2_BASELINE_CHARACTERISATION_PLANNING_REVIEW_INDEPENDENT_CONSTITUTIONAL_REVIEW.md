## 3. Adversarial planning checks

### Early catastrophic failure

Stopping after an alarming first result would give a vivid anecdote, not the frozen baseline. The plan correctly pauses for consequential and integrity review, then resumes the registered matrix if measurement remains safe. Only identity, privacy, artifact, harness, or comparability failure terminates execution. A truncated result cannot silently receive PASS.

### Context-selection bias

Selecting Stage 2 fixtures after viewing Stage 1 would bias factor findings. The twelve sentinels are therefore fixed before any live call. All 23 fixtures still receive the two most decision-relevant endpoints: minimal and mixed/full.

### NOACTION balance

Only two inert fixtures are used. This yields wider NOACTION uncertainty, which must be disclosed, but is constitutionally preferable to inventing unsupported owner-message categories merely for equal sample sizes. Per-action reporting prevents the small stratum being hidden.

### Unit 1 versus Unit 2 code ownership

The current explicit task's smoke method cannot accept a matrix through environment configuration. Adding a Unit 2-only JUnit campaign driver is not a Unit 1 correction and does not justify editing the harness. The proposed one-file surface is plausible but still requires Scope Lock, Implementation Plan, and Boundary Review.

### Model identity

`qwen2.5-coder:7b` can move behind a tag. The digest-or-equivalent rule prevents batches from being combined across mutable model identity. Missing immutable identity requires governance, not assumption.
