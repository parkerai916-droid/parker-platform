## 8. Is Family C sufficiently constrained against brittle keyword/rule matching?

Yes, tested adversarially. A concrete failure scenario was constructed: a hypothetical Family C implementation using a naive rule such as "classify REMEMBER whenever the input contains the word 'remember.'" Such a rule would score perfectly on the corpus's direct explicit-REMEMBER fixtures (all contain the literal word) while producing false positives on: "Do you remember where I put my keys?" (a question); "I remember my childhood home fondly" (an ordinary fact); "The article said, 'remember to stay hydrated'" (quoted, not addressed to Parker); "If you were to remember one thing, remember this" (hypothetical/rhetorical); and a GOAL-bearing sentence that happens to contain "remember" incidentally. Checked each against Section 4's nine mandatory negative categories: the question case is covered ("a question about remembering"); the ordinary-fact case is covered ("an ordinary statement of fact that happens to contain memory-related vocabulary"); the quoted case is covered explicitly; the hypothetical case is covered explicitly; the GOAL-overlap case is covered explicitly ("GOAL-like language containing vocabulary overlapping with REMEMBER's own trigger surface"). All five constructed failure modes fall within Section 4's required negative-coverage set, and Section 4's own binding language ("A Family C experiment that has not exercised this negative surface... may not proceed to Unit 3-D") makes this a hard precondition, not a suggestion. **The Scope Lock does force future experiment design to expose this risk.**
