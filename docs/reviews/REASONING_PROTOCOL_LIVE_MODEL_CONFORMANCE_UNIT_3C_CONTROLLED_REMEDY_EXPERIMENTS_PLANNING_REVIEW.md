## 6. Campaign-structure analysis

**Determination: A — one governed Unit 3-C campaign containing isolated experimental arms, with mandatory arm-level fault isolation.**

Reasoned as follows, against each factor the task requires:

- **Causal attribution / experiment independence:** causal isolation is a property of how arms are measured and recorded, not of how many campaign identities exist. Unit 2-D's own accepted design — DQ1 through DQ6 run as distinct, independently-ledgered tracks within one campaign — already demonstrated, in this programme's own accepted evidence, that track-level (arm-level) isolation is sufficient to prevent false attribution between sub-questions; nothing about separate campaign identities would have made that isolation stronger.
- **Fixture comparability / shared control requirements:** Families A, B, and C all require the identical unmodified-production control arm run under identical fixtures, context, model, and configuration (Section 10). Running that control once, inside one campaign, and attributing its results to all three family comparisons is more trustworthy than three independently-run control arms, which would introduce exactly the kind of incidental cross-run drift (timing, server state, minor environmental variance) that separate campaigns would need to reconcile after the fact rather than avoid by construction.
- **Artifact identity / execution integrity:** one campaign identity, one manifest, one hash-verification pass, and one execution-approval review cover the same underlying evidence-gathering activity that three separate campaigns would cover three times, at three times the governance overhead, without a compensating trustworthiness benefit.
- **Campaign failure isolation:** this is the genuine argument for separate campaigns, and it is taken seriously — but it is satisfied by mandatory arm-level fault isolation (separate track ledgers, separate checkpoint/halt state per family-arm, mirroring Unit 2-D's own warmup/production-track/candidate-track design) rather than by separate campaign identities. A measurement defect specific to one family's arm must not silently halt or corrupt another family's arm's evidence collection; this is a binding design requirement a future Scope Lock must freeze, not an argument for tripling governance overhead.
- **Family C's special false-positive risk:** addressed at the arm level, not the campaign level. Family C's arm requires its own stricter internal ordering (adversarial-fixture-first, per Unit 3-B Section 4) and its own more conservative review checkpoint (Section 18), exactly as Unit 2-D's own candidate-track already operated under different rules from its production-track within one campaign.
- **Remedy neutrality:** a shared campaign does not, by itself, invite a "race" framing — Unit 3-B's own binding interpretive rule (Section 3) and comparison discipline (Section 10) already prohibit reading any comparison as selecting a winner, regardless of campaign structure. This concern is addressed by discipline in reporting, not by campaign fragmentation.
- **Cost and unnecessary duplication:** three separate campaigns would triple the shared base-corpus administration and the shared control arm for no evidentiary gain — a straightforward, avoidable cost.

No structure was identified that provides stronger causal isolation than arm-level isolation within one campaign (Option C); no obstacle was identified that would make campaign-structure planning premature (Option D) given the frozen Unit 3-A and Unit 3-B governance already available.

## 7. Family A experiment concept — decision/rendering separation

**Independent variable:** whether action-selection is obtained as a separate, prior step isolated from free-text rendering of that selection's content, versus the current single joint call that performs both simultaneously.

**Held identical to the control:** fixture text, context profile, model identity (digest-verified), inference configuration (Section 13), the parser's tag vocabulary, and the fixture-level definition of the expected action.

**What the minimum experiment must measure, and why it must go beyond DQ5:** DQ5 measured only decision-only accuracy on the single positive fixture that already fails under the joint task. A controlled Family A experiment must decompose the pipeline's error into two separately measured quantities: (a) decision-step accuracy — whether an isolated decision step selects the fixture's expected action, measured across the full fixture set including negative and adversarial fixtures, not the one positive fixture DQ5 exercised; and (b) rendering-step fidelity and representation validity — given a *known-correct* decision, whether a subsequent rendering step reliably produces valid, faithful content. Neither quantity was measured by DQ5. This does not require designing or committing to a two-call *production* architecture; it requires only measuring these two capabilities as independently as the current single-call architecture allows them to be isolated, exactly as an experiment, not a redesign.

**False-positive testing:** the decision step must be run against the full adversarial/negative fixture set (Section 9), not the positive fixtures alone — this directly closes the gap DQ5 left open, since DQ5 never tested Family A's mechanism against a single negative fixture.

**Content fidelity:** measured on the rendering step's output using Unit 3-A Section 8's unmodified definition, comparing content produced under a known-correct-decision condition against the joint task's own content output.

**What would count as evidence against Family A:** if decision-only accuracy on the *full* fixture set does not exceed joint-task accuracy by a non-trivial margin beyond the single fixture DQ5 already showed; if the decision step's own false-positive rate on negative fixtures is no better than, or worse than, the joint task's; or if rendering fidelity/validity given a known-correct decision turns out to already be near-perfect under the joint task, undermining the premise that rendering (not decision) was ever the bottleneck.

**Not addressed here:** how or whether a two-call design would ever be wired into production. That is Unit 4's question, contingent on Unit 3-E selection, contingent on Unit 3-D comparison, contingent on qualification-tier evidence this exploratory concept does not itself produce.

## 9. Family C experiment concept — deterministic/rule-assisted handling

**What the minimum lawful exploratory experiment must prove:** per Unit 3-B Section 4's own binding language, correctly recognizing the canonical direct-instruction case proves nothing by itself. The minimum experiment must measure whether *any* deterministic/rule-assisted mechanism achieves an acceptable joint outcome across both the canonical positive case *and* the full mandatory nine-category adversarial/negative set (Section 11) — specifically, whether its false-positive rate on that adversarial set is no worse, and ideally markedly better, than the current joint-task model's own observed false-positive behavior.

**Integration-architecture question deferred, not decided:** whether Family C should ultimately operate as an independent pre-classifier, a constrained rule-assisted signal alongside the model, or another integration form is an architecture decision this Planning Review does not make, because it would itself be premature remedy design ahead of knowing whether *any* rule-based mechanism has a trustworthy standalone false-positive profile at all. The recommended minimum experiment therefore measures a to-be-defined rule's *standalone* accuracy and false-positive profile against the full fixture set — evaluated independently of any integration architecture — deferring the pre-classifier-versus-signal choice to whichever later governance step is informed by that measurement. No rule, regex, or keyword pattern is authored, chosen, or implied anywhere in this document.

## 12. Repetition and evidence-scale analysis

**No specific repeat count is justified by current evidence, and none is invented here.** Reasoned as follows: Unit 2's qualification-scale design (≥30/cell, ≥300-exposure) is constitutionally reserved for qualification tier, not exploratory tier (Unit 3-B Section 6) — applying it here would misrepresent exploratory evidence as qualification evidence. Unit 2-D's own triage-grade counts (DQ1's ten attempts, DQ5's five attempts) were pragmatic choices for *those* specific diagnostic questions, not a general-purpose number; DQ1's near-deterministic finding (9/10, later corroborated) establishes high repeatability only for the one fixture and condition it tested, and cannot be safely generalized to justify a count for the twenty-two other fixtures or for Family B/C's own candidate mechanisms, whose variance is entirely unknown.

**A structural principle can be recommended even without a specific number:** repetition should be uniform between a family's own control and candidate arms (so comparison is matched), and should be justified per fixture class based on that fixture's own known or estimated variance — a fixture with established high consistency (like the principal direct-REMEMBER fixture, per DQ1) may reasonably use a smaller count than a fixture whose variance is entirely unmeasured — rather than one blanket count applied uniformly across all fixtures regardless of behavior. This variance-informed principle is recommended for a future Scope Lock to adopt; the specific numbers remain unresolved, to be set with explicit reasoning at Scope Lock or Implementation Plan tier.

**Explicitly stated, per this task's own requirement:** no Unit 3-C exploratory-tier result, at any repeat count discussed above, satisfies Unit 3-A's qualification thresholds unless a future, separate governance step expressly demonstrates that it does. Exploratory evidence answers only whether a family deserves further investment (Unit 3-B Section 6).

## 13. Family C safety burden

**Determination: B — Family C requires additional exploratory/adversarial evidence, but not a different contractual threshold.**

Reasoned as follows: Unit 3-A Section 7's zero-observed-false-positive requirement is already the strictest threshold constitutionally available — zero is the floor; no numerically "stricter" threshold exists to assign Family C (ruling out Option C). What legitimately differs for Family C is not the *threshold* but the *evidence burden* needed to gain confidence that the threshold is met: a rule-based mechanism's characteristic failure mode is systematic, keyword-triggered false-positives across many phrasing variations, qualitatively different from a model's diffuse statistical error mode — genuine confidence that Family C's false-positive rate is truly zero, not merely zero-in-a-limited-sample, plausibly requires deliberately broader, more systematically adversarial exposure than Families A or B need to reach equivalent confidence. This is a difference in the *breadth of exploratory/adversarial evidence* Family C must produce before its own qualification-tier attempt would even be credible, not a different contractual number.

**Distinguished explicitly, per this task's requirement:** the *contractual safety requirement* (Unit 3-A Section 7, zero-tolerance) is unchanged and sufficient. The *exploratory evidence burden* is higher for Family C — proportionally broader adversarial-fixture coverage, ordered adversarial-fixture-first per Unit 3-B Section 4 — but no specific breadth multiplier is invented here. The *qualification evidence burden*, if Family C is ever escalated that far, remains the same ≥300-exposure zero-event structure Unit 3-A Section 4 already defines for every remedy, not a Family-C-specific number.

## 16. Adaptive-experimentation prohibition and control

**Determination: resolved — pre-registration required across all three families; no run-inspect-tweak-rerun loop; no silent mid-experiment mutation.**

Recommended, binding-on-a-future-Scope-Lock requirements: (1) the exact candidate mechanism definition — prompt variant text for Family B, decision/rendering split protocol for Family A, rule definition for Family C — must be fixed in writing in the future Implementation/Execution Plan before any live call in that experiment begins; (2) the fixture corpus must be frozen for the duration of the experiment, with no fixture added, removed, or edited mid-run; (3) the repetition schedule must be frozen in advance, with no ad hoc extension because early results look promising or concerning; (4) an explicit stopping rule (a fixed total call count, or a pre-specified fail-closed condition per Section 17) must be stated in advance, never an open-ended "keep going until it looks good" rule; (5) one campaign identity per registered experiment design — a genuinely new candidate mechanism desired after observing results requires a new, separately governed experiment, not a silent mutation of the one already running. This generalizes and reuses the same exact-once, immutable-corpus, pre-registered-schedule discipline Unit 2-D's own driver already implemented and was independently verified not to violate.

**Separating legitimate exploratory iteration from registered evidence:** any informal iteration on candidate wording or rule design that a team wishes to perform before committing to a registered set must happen entirely outside any live-model-call, governed campaign — through non-live reasoning, or, if live informal exploration is genuinely needed, through its own explicitly-labeled, clearly-separate diagnostic activity whose results are never cited as if they were the registered experiment's own evidence, mirroring how Unit 2-D itself was kept clearly distinct from Unit 2's own qualification track.

## 17. Stop-condition strategy

**A. Measurement-invalidating failures** — wrong model, wrong commit, configuration drift (including Ollama server/model-file drift per Section 14), corrupted artifact, harness defect, parser/classifier measurement defect, unauthorized downstream action, call-accounting failure — should fail closed, consistent with the hard-stop-versus-semantic-failure distinction already established and reused throughout Unit 2-D's governance chain.

**B. Remedy-performance failures** — wrong semantic action, representation failure, false-positive REMEMBER, false-positive GOAL, content-fidelity failure — are generally evidence and should be recorded, not concealed, per Unit 3-B Section 12's own already-frozen language.

**Whether constitutionally dangerous false-positive behavior should trigger a safety stop while preserving the observation:** recommended — not as an automatic hard stop mechanically inherited from Unit 2's Stage 0 gate (which was justified by different facts: a real production-adjacent qualification attempt, not an isolated, downstream-isolated exploratory experiment — Unit 3-B Section 13 already makes any Unit 3-C experiment's actual downstream consequence structurally impossible regardless of stop conditions), but as a **threshold-triggered manual review checkpoint**: an abnormal *concentration* of false-positive REMEMBER/GOAL events within a short span (a future Scope Lock must define what "abnormal concentration" means, not invented here) is more consistent with a harness or rule-wiring defect masquerading as remedy evidence than with genuine remedy performance, and conflating the two would corrupt the evidence record. This recommends a governance requirement to define such a checkpoint — a pause for manual harness-integrity review, not an automatic experiment-ending hard stop — reasoned specifically for why Unit 2's Stage 0 behavior does not automatically transfer, rather than inherited without reasoning.
